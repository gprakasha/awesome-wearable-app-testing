# Contributing

Thanks for helping make wearable app testing easier to understand and apply. Contributions of resources, practical test scenarios, corrections, and platform-specific guidance are welcome.

## Before you submit

- Make sure the resource or scenario is relevant to testing wearable apps or phone–wearable experiences.
- Prefer official documentation and actively maintained projects.
- Check that the link works and that the information is not already listed.
- Use an existing README heading when possible. If proposing a new section, keep it focused and useful to readers.
- Be specific about platform, device, OS-version, and simulator or hardware limitations. Do not claim a tool supports watch testing unless that support is documented.
- For test scenarios, describe the setup, action or failure condition, expected result, and whether physical hardware is needed.
- Do not include private user data, credentials, or confidential material in examples.

## Resource format

Add a concise bullet with a descriptive link and a short explanation of how it helps with wearable app testing:

```markdown
- [Resource name](https://example.com) — What it does and how it helps with wearable app testing.
```

## Pull requests

- Explain what you added or changed and why it is useful.
- Keep changes focused and preserve the README's existing Markdown style.
- If you update a platform or tool recommendation, note relevant support limitations and avoid implying broader coverage than the source documents.
